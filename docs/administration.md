# Административный API

Эта инструкция нужна администратору при управлении пользователями и проверке прав API. Для первого входа и настройки OIDC см. [аутентификацию](authentication.md).

Все административные маршруты находятся под `/api/v1`. Гостевая роль сохраняет согласованные
права чтения предметных разделов, но не получает `users.read` и не может просматривать пользователей,
роли или сопоставления OIDC. Администратор читает и изменяет административные реестры.
Изменяющие запросы всегда передают CSRF-токен из
`GET /api/v1/auth/session` в заголовке `X-CSRF-Token`.

| Область | Чтение | Изменение |
| --- | --- | --- |
| Пользователи и роли | `users.read` | `users.write` |
| Соответствия ролей OIDC | `users.read` | `users.write` |
| Настройки приложения (`/app-settings`) | `settings.read` | `settings.write` |
| Нормализаторы | `normalizers.read` | `normalizers.write` |


Гость — аутентифицированный пользователь с ролью только для чтения; он может читать доступные ему нормализаторы через ту же cookie-сессию. Администратор создаёт пользователей в разделе «Администрирование». При вызове API сначала выполните локальный вход, затем получите CSRF-токен через `GET /api/v1/auth/session` и передайте его в `X-CSRF-Token` при изменении. Пароль пользователя не входит в ответ API. Не сохраняйте пароль в истории команд или текстовых примерах.

`PUT /api/v1/app-settings/{key}` и `PATCH /api/v1/normalizers/{id}` требуют актуальное
поле `version`. При устаревшей версии API возвращает `409 version_conflict` с
`details.current_version`; повторите запрос после чтения текущей записи. Настройки
создаются только кодом/миграциями: HTTP API позволяет читать и менять лишь уже
зарегистрированные ключи. Поле `rule` нормализатора является JSONB-объектом v1;
его структура и ECS-совместимость проверяются перед созданием или заменой.
