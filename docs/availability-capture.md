# Захват времени доступности и доказательства полноты окна

Новые нормализованные события получают `availability_at` из времени commit в потоке PostgreSQL `pgoutput`. Событие и его маркер записываются в одной транзакции. Декодер сохраняет фактическое время commit маркеров и долговечную позицию LSN в другой транзакции, а затем подтверждает эту позицию слоту. Повтор после сбоя идемпотентен. Старые события не получают выдуманное `availability_at`. Сохранение ретроспективных точек по `backend_processed_at` разрешено только до доказанной границы первой инициализации; неизвестная область остаётся доступна лишь для явно выбранного read-only preview. Порядок обновления и две долговечные границы описаны в [инструкции агрегатов](aggregates.md#обновление-capture).

## Запуск и права

Оба Compose режима используют PostgreSQL 18 с `wal_level=logical` и `max_slot_wal_keep_size=1GB`. `wal-bootstrap` создаёт узкую публикацию, постоянный logical slot и отдельную роль `diploma_wal_reader`; затем запускается `wal-decoder`. API начинает принимать новые рабочие события после проверки декодера. Роль декодера не читает таблицу `parsed_logs`.

В development `python scripts/prepare_dev_kafka.py` создаёт `.dev/wal_reader_password`. По умолчанию пароль совпадает с `WAL_READER_PASSWORD` в Compose; при своём пароле задайте ту же переменную в `.env`. В production задайте `WAL_READER_PASSWORD_FILE` и `WAL_DATABASE_URL_FILE`. Файл URL должен содержать адрес PostgreSQL с ролью `diploma_wal_reader` и тем же паролем, например `postgresql+psycopg://diploma_wal_reader:<пароль>@postgres:5432/<база>`. Секреты хранятся вне репозитория.

## Контроль ресурса и отказ

`python -m app.wal_health --details` и healthcheck `wal-decoder` показывают состояние слота, долговечный LSN, удержанный WAL, доступный бюджет и heartbeat. Захват запрещает новые рабочие записи, если слот отсутствует или потерян, декодер отстаёт, heartbeat старше 20 секунд либо остаток `safe_wal_size` меньше 256 MiB. Kafka offset при таком отказе не подтверждается. Другие транзакции PostgreSQL всё равно могут расходовать WAL, поэтому конечный лимит не обещает неограниченный простой.

При `wal_budget_exhaustion_approaching` восстановите декодер и проверьте освобождение удержанного WAL до достижения лимита. При `wal_unavailable` остановите запись новых событий и не пересоздавайте слот автоматически: пропущенный commit поток уже нельзя достоверно восстановить через `backend_processed_at`. Проверьте состояние PostgreSQL, публикации, слота и декодера; решение о восстановлении и границе данных принимает оператор. `VACUUM FREEZE` не заменяет удержанный WAL.

## Пустые окна

`complete` для пустого окна требует сохранённых подписанных аттестаций фактического входа без разрывов, подтверждённой обработки соответствующих позиций Kafka без отставания и материализованного WAL барьера. Probe регистрируется оператором с открытым ключом Ed25519, UUID источника и поколением конфигурации входа; его отчёт содержит UTC интервал, последовательность и позиции Kafka. Оператор обязан связать регистрацию с реальным настроенным входом и отозвать probe при смене конфигурации. Обычные входы без такой аттестации получают `unknown`. Известная остановка входа или обработки даёт `interrupted`. Состояние учётной записи агента и одиночный heartbeat не подтверждают покрытие интервала.

Для непрерывности обработки сохраняется последовательность Kafka-checkpoint одного экземпляра consumer с промежутками не более 10 секунд: она должна охватывать всё окно. Штатная остановка и возобновление сохраняют интервал остановки. После аварии или при пропущенных отметках отсутствие непрерывной цепочки даёт `unknown`, даже если свежий checkpoint больше не показывает отставания.

Проверки: `python -B scripts/check_pgoutput_gate.py` для изолированной PostgreSQL, `python -B scripts/agent_test_profiles.py backend-db`, `python -B scripts/agent_test_profiles.py kafka-integration`, а также `smoke-development --check-only` и `smoke-production --check-only` для resolved Compose. Временные ресурсы профилей находятся в `.test_runs/runs/<run-id>/` и удаляются скриптами после успешного запуска.
