# Внешние OpenSearch-совместимые источники

Эта инструкция нужна администратору при подключении индексера и проверке чтения внешних событий. Для поиска и карточки событий используйте страницу «События».

## Действия в интерфейсе

1. На странице «Подключения» создайте внешнее подключение к HTTPS-адресу индексера. Введите учётные данные с правами чтения, сохраните и при частном CA загрузите его PEM-цепочку. Проверьте подключение и доступные индексы или потоки. Ошибка TLS требует проверки CA и имени хоста; не отключайте проверку сертификата.
2. На странице «Источники» зарегистрируйте конкретный индекс, поток или допустимый шаблон. Новый источник выключен; после проверки включите его. Если подключение или CA изменились, проверьте их снова и включите связанные источники вручную.
3. На странице «События» выберите внешний источник, выполните поиск и фильтрацию, раскройте строку. Документы читаются из индексера; локальный нормализатор к ним не применяется и Kafka не участвует. При недоступности индексера проверьте его состояние и права учётной записи, сохраняя источник для повторной попытки.

Для сравнения выберите локальный Kafka-источник на той же странице. Он читает сохранённые в PostgreSQL нормализованные события и позволяет просмотреть связанный сырой лог. Состав полей фильтрации определяется выбранным источником.

Адрес индексера должен разрешаться и быть достижимым **из контейнера API**. `127.0.0.1` в настройке подключения обозначает сам контейнер API, а не хост с индексером. Имя хоста в URL должно совпадать с сертификатом индексера; при частном CA загрузите его цепочку для этого подключения. Внешний доступ не проходит через веб-proxy приложения.

Внешние подключения используют Basic Auth через проверяемый HTTPS. Создайте постоянный ключ Fernet вне PostgreSQL и репозитория:

```shell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Передайте результат как `EXTERNAL_SECRET_KEY` через хранилище секретов или закрытый файл окружения. Сохраняйте тот же ключ при перезапусках и резервном копировании. Потеря ключа делает пароли подключений нечитаемыми; отсутствие или неверное значение вызывает явную ошибку, а открытый пароль не сохраняется. Для смены пароля подключения выполните PATCH поля `password`; отсутствие поля сохраняет прежнее зашифрованное значение. Для ротации ключа остановите API, сохраните БД и старый ключ, закройте доступ к `DATABASE_URL`, `EXTERNAL_OLD_KEY`, `EXTERNAL_NEW_KEY` и выполните `python scripts/rotate_external_key.py`. Скрипт перешифровывает все строки одной транзакцией и откатывает её, если хотя бы одну строку нельзя расшифровать. Запустите API с новым `EXTERNAL_SECRET_KEY`; сохраняйте старый ключ до проверки всех подключений. Нельзя менять только переменную ключа.

`/api/v1/external-connections` управляет подключениями к индексеру. `PUT /{id}/ca` принимает сырую цепочку PEM CA с типом `application/x-pem-file` и размером 1–65536 байт; `DELETE /{id}/ca` удаляет её. Системные корневые CA продолжают действовать. Загруженный CA влияет только на это подключение. Изменение подключения или CA выключает его источники до повторной проверки. DTO возвращает `has_password` и `has_ca`, но не сами значения. `POST /{id}/test` и `GET /{id}/indices` требуют `connections.write`; последний выдаёт до 100 имён индексов на страницу. Прочие изменения также требуют `connections.write`, чтение метаданных — `connections.read`.

`/api/v1/external-sources` управляет внешними источниками с разрешением `sources.write`; чтение требует `sources.read`. Явно задайте `target_type`: `index`, `index_pattern`, `data_stream` или `data_stream_pattern` и ровно соответствующее поле: `index_name`, `index_pattern`, `data_stream_name` или `data_stream_pattern`. Имена содержат строчные ASCII-буквы, цифры, `.`, `_`, `-` и не начинаются с `.` или `_`. Шаблоны допускают `*` и `?` и обязаны содержать хотя бы один такой символ. Запятые, пути API и query DSL запрещены. Шаблоны применяются к конкретным логическим именам. Новый источник выключен; при включении проверяется хотя бы одна доступная цель того же типа. Это разрешает приложению только чтение, не изменяет индексер и не запускает Kafka consumer. `/sources` по-прежнему перечисляет только Kafka-источники с `source_type: "kafka"`; внешние источники имеют свой список с `source_type: "external"`. Прежние URL и операции Kafka-источников не меняются.

Учётной записи индексера нужны права на список открытых индексов и разрешение data streams через `GET /_resolve/index/*`. В официальном образе Wazuh `5.0.0-beta5` встроенная роль `readall` разрешала `_resolve/index/*`, но `_cat/indices` дополнительно требовал операции чтения метаданных `indices:monitor/settings/get`, `indices:monitor/stats`, `cluster:monitor/state`, `cluster:monitor/health`. Предоставьте эти права, если список индексов или `POST /test` возвращает 403. `GET /external-connections/{id}/indices` перечисляет конкретные индексы, `GET /external-connections/{id}/data-streams` — логические data streams. Подлежащие индексы `.ds-*` не выдаются как имена потоков. Запросы метаданных имеют сетевой timeout 5 секунд, общий срок чтения 15 секунд, предел ответа 1 MiB и 10 000 обнаруженных имён. Перенаправления запрещены.

Для отдельной проверки Wazuh используйте [официальный релиз Wazuh `v5.0.0-beta5`](https://github.com/wazuh/wazuh/releases/tag/v5.0.0-beta5) в изолированной тестовой установке с HTTPS и тестовым CA. Создайте тестовый ECS-ориентированный индекс и документ административной учётной записью индексера, а приложению выдайте отдельную учётную запись только для чтения документов и метаданных. Войдите в приложение администратором, создайте внешнее подключение к адресу, достижимому из API-контейнера, загрузите CA и проверьте список индексов. Зарегистрируйте и включите источник для конкретного индекса и, отдельно, источник для его шаблона. Обычный индекс проверяет чтение OpenSearch, но не Wazuh findings.

Для Wazuh findings создайте тестовое событие через официальную настройку Wazuh data stream. `GET /api/v1/external-connections/{id}/data-streams` должен показать логический поток `wazuh-findings-v5-security`; `_cat/indices` может показать только подлежащий индекс `.ds-*`. Создайте и включите `target_type: "data_stream", data_stream_name: "wazuh-findings-v5-security"` и `target_type: "data_stream_pattern", data_stream_pattern: "wazuh-findings-v5-*"`. Найдите документ на странице «События» и убедитесь, что в `parsed_logs` не появилась запись.

Для повторяемой проверки без рабочего индексера запустите из корня репозитория [профиль `external-end-to-end`](agent-test-profiles.md). Он использует настоящий Wazuh Indexer 5.0.0-beta5 с синтетическими документами формы WCS и упрощёнными mappings, но без Wazuh Manager; результат не подтверждает реальный конвейер findings Manager. Учётная запись читателя имеет доступ только к тестовым индексам и потокам, metadata и PIT. Успех фильтра на синтетических данных не обещает одинаковые поля произвольной установки Wazuh.
