# Внешние OpenSearch-совместимые источники (TASK-10)

Внешние подключения используют Basic Auth через проверяемый HTTPS. Создайте постоянный ключ Fernet вне PostgreSQL и репозитория:

```shell
python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
```

Передайте результат как `EXTERNAL_SECRET_KEY` через хранилище секретов или закрытый файл окружения. Сохраняйте тот же ключ при перезапусках и резервном копировании. Потеря ключа делает пароли подключений нечитаемыми; отсутствие или неверное значение вызывает явную ошибку, а открытый пароль не сохраняется. Для смены пароля подключения выполните PATCH поля `password`; отсутствие поля сохраняет прежнее зашифрованное значение. Для ротации ключа остановите API, сохраните БД и старый ключ, закройте доступ к `DATABASE_URL`, `EXTERNAL_OLD_KEY`, `EXTERNAL_NEW_KEY` и выполните `python scripts/rotate_external_key.py`. Скрипт перешифровывает все строки одной транзакцией и откатывает её, если хотя бы одну строку нельзя расшифровать. Запустите API с новым `EXTERNAL_SECRET_KEY`; сохраняйте старый ключ до проверки всех подключений. Нельзя менять только переменную ключа.

`/api/v1/external-connections` управляет подключениями к индексеру. `PUT /{id}/ca` принимает сырую цепочку PEM CA с типом `application/x-pem-file` и размером 1–65536 байт; `DELETE /{id}/ca` удаляет её. Системные корневые CA продолжают действовать. Загруженный CA влияет только на это подключение. Изменение подключения или CA выключает его источники до повторной проверки. DTO возвращает `has_password` и `has_ca`, но не сами значения. `POST /{id}/test` и `GET /{id}/indices` требуют `connections.write`; последний выдаёт до 100 имён индексов на страницу. Прочие изменения также требуют `connections.write`, чтение метаданных — `connections.read`.

`/api/v1/external-sources` управляет внешними источниками с разрешением `sources.write`; чтение требует `sources.read`. Явно задайте `target_type`: `index`, `index_pattern`, `data_stream` или `data_stream_pattern` и ровно соответствующее поле: `index_name`, `index_pattern`, `data_stream_name` или `data_stream_pattern`. Имена содержат строчные ASCII-буквы, цифры, `.`, `_`, `-` и не начинаются с `.` или `_`. Шаблоны допускают `*` и `?` и обязаны содержать хотя бы один такой символ. Запятые, пути API и query DSL запрещены. Шаблоны применяются к конкретным логическим именам. Новый источник выключен; при включении проверяется хотя бы одна доступная цель того же типа. Это разрешает приложению только чтение, не изменяет индексер и не запускает Kafka consumer. `/sources` по-прежнему перечисляет только Kafka-источники с `source_type: "kafka"`; внешние источники имеют свой список с `source_type: "external"`. Прежние URL и операции Kafka-источников не меняются.

Учётной записи индексера нужны права на список открытых индексов и разрешение data streams через `GET /_resolve/index/*`. В официальном образе Wazuh `5.0.0-beta5` встроенная роль `readall` разрешала `_resolve/index/*`, но `_cat/indices` дополнительно требовал операции чтения метаданных `indices:monitor/settings/get`, `indices:monitor/stats`, `cluster:monitor/state`, `cluster:monitor/health`. Предоставьте эти права, если список индексов или `POST /test` возвращает 403. `GET /external-connections/{id}/indices` перечисляет конкретные индексы, `GET /external-connections/{id}/data-streams` — логические data streams. Подлежащие индексы `.ds-*` не выдаются как имена потоков. Запросы метаданных имеют сетевой timeout 5 секунд, общий срок чтения 15 секунд, предел ответа 1 MiB и 10 000 обнаруженных имён. Перенаправления запрещены.

Для отдельной проверки Wazuh используйте [официальный релиз Wazuh `v5.0.0-beta5`](https://github.com/wazuh/wazuh/releases/tag/v5.0.0-beta5) в тестовой установке с HTTPS и тестовым CA. Создайте в индексере конкретный индекс `diploma-task10-smoke-v1-000001` административной учётной записью, затем добавьте безопасный документ:

```shell
curl --cacert test-ca.pem --user indexer-admin -X PUT "$INDEXER_URL/diploma-task10-smoke-v1-000001"
curl --cacert test-ca.pem --user indexer-admin -H "Content-Type: application/json" -X PUT "$INDEXER_URL/diploma-task10-smoke-v1-000001/_doc/1" -d '{"@timestamp":"2026-09-30T00:00:00Z","event":{"kind":"event"},"message":"TASK-10 smoke"}'
```

Отдельной тестовой учётной записи дайте право чтения метаданных. Войдите в приложение администратором, создайте внешнее подключение к HTTPS URL индексера с этой учётной записью и загрузите `test-ca.pem` через `PUT /api/v1/external-connections/{id}/ca` с `Content-Type: application/x-pem-file`. `GET /{id}/indices` должен содержать `diploma-task10-smoke-v1-000001`; создайте и включите источники с `target_type: "index", index_name: "diploma-task10-smoke-v1-000001"` и `target_type: "index_pattern", index_pattern: "diploma-task10-smoke-v1-*"`. Обычный индекс проверяет путь чтения индекса, но не Wazuh findings.

Для Wazuh findings создайте тестовое событие через официальную настройку Wazuh data stream. `GET /{id}/data-streams` должен показать логический поток `wazuh-findings-v5-security`; `_cat/indices` может показать только подлежащий индекс `.ds-*`. Создайте и включите `target_type: "data_stream", data_stream_name: "wazuh-findings-v5-security"` и `target_type: "data_stream_pattern", data_stream_pattern: "wazuh-findings-v5-*"`. Убедитесь, что в `parsed_logs` не появилась запись. Чтение документов относится к TASK-12.
