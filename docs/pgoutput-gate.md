# Прототип pgoutput для TASK-30

Запуск из корня проекта:

```powershell
python -B scripts/check_pgoutput_gate.py
```

Нужны Docker Compose и Python-зависимости общего контура `backend-db`. Скрипт
использует `scripts/agent_test_profiles.py`, проектные development Compose-файлы,
отдельную тестовую базу, том, сеть, loopback-порт и временные секреты. Он включает
`wal_level=logical` и `max_slot_wal_keep_size=64MB` только в изолированном
эксперименте. `track_commit_timestamp=on` включён только для независимого
сравнения полученной метки; сам прототип считывает её из `pgoutput`.

Прототип создаёт публикацию одной синтетической таблицы, постоянный слот
`pgoutput` и читает сообщения протокола версии 1 с помощью
`pg_logical_slot_peek_binary_changes`. Он проверяет время commit и идентификаторы
маркеров, `VACUUM FREEZE` при неработающем читателе, удержание WAL,
блокировку писателя и барьера на одном источнике и расположение commit по обеим
сторонам реальной границы времени БД. Результаты фиксируются в таблице до
продвижения слота. Перезапуск PostgreSQL до подтверждения приводит к повторной
выдаче без потери и дублей; после подтверждения и второго перезапуска результаты
и позиция сохраняются. При искусственном превышении 64 МБ WAL и checkpoint
слот становится `lost`, чтение возвращает ошибку `55000`, а непрочитанный маркер
не классифицируется.

Последний прогон 02.11.2026: PostgreSQL 18.6 (`postgres:18`), профиль
`backend-db`, проект `diploma_t21_04a84549e3`, адрес `127.0.0.1:47524`.
Проверки прошли, `confirmed_flush_lsn=0/1BF1C78`; удержанный WAL до чтения
составлял 552 байта. Каталог
`.test_runs/runs/pgoutput-gate-8265efc0d773487ab9a382807e4a886b/` удалён,
Docker-инвентарь совпал с исходным. Использовались синтетические секреты;
основные переменные контура: `POSTGRES_PASSWORD`, `POSTGRES_PASSWORD_FILE`,
`POSTGRES_DB`, `POSTGRES_BIND`, `TEST_DATABASE_URL`, `COMPOSE_PROJECT_NAME`,
`TEMP`, `TMP`, `TMPDIR`.

Это проверка механизма на синтетической схеме, а не реализация приложения.
SQL-функции чтения и продвижения слота использованы для прототипа; постоянный
потоковый декодер, отдельная роль, безопасное сохранение прогресса в приложении,
ограничение памяти и WAL в рабочих условиях, обработка потери слота и запуск в
development/production должны быть проверены отдельно. Эксперимент создаёт
ситуацию ошибки, но не проверяет остановку рабочего consumer, поскольку её ещё
нет. Полнота источника и все требования к рабочим окнам также остаются открытыми.
Результат не означает готовности TASK-30 к ревью.

Дополнительный прогон 02.11.2026 проверил новый риск: реальное соединение
логической репликации через libpq и разбор сообщений приложением. Протокол
`START_REPLICATION` и SQL-чтение вернули одинаковые маркеры и время commit;
дальнейшие проверки повторной выдачи, vacuum, границы и утраты WAL прошли.
Команда та же; PostgreSQL 18.6, `backend-db`, проект `diploma_t21_cbd4a5b20e`,
адрес `127.0.0.1:20125`. Каталог
`.test_runs/runs/pgoutput-gate-9f544431f9fc4e638f295476370284fa/` удалён,
Docker-инвентарь совпал с исходным. Этот тест не проверяет подтверждение
LSN через поток, рабочую роль, постоянный процесс или остановку consumer.
