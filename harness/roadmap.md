Этот файл показывает состояние этапов и ведёт к их постановкам и планам. Для новых этапов цель, границы и критерии приёмки человек и Главный архитектор фиксируют в `stage<n>_assignment.md`, который человек передаёт Этапному архитектору. Тот вместе с человеком уточняет реализацию и порядок задач в `plan<n>.md` внутри поставленных границ. Фактический результат фиксируется в разделе «Итог этапа» плана.

При ревью Главного архитектора проверена ветка `stage-1-data-pipeline` на коммите `d491c8f`. Независимо прошли профили `kafka-integration` (422 passed, 1 skipped), `end-to-end` (Fluent Bit → Kafka → ECS → PostgreSQL → React, включая восстановление после перезапуска) и `external-end-to-end` (Wazuh Indexer 5.0.0-beta5 с синтетическими документами, read-only HTTPS, поиск и фильтрация через React без копирования в PostgreSQL). В проверке `frontend` типизация, lint и форматирование прошли; один из 204 тестов превысил таймаут при полном прогоне и прошёл при адресном повторе. У Этапного архитектора полный frontend-набор и оба development/production smoke-профиля прошли ранее; эти результаты не считаются новыми прогонами Главного архитектора. Ограничения проверки Wazuh без Manager и агента без отдельного физического хоста указаны в «Итоге этапа».

Этап 2 ограничен собственными нормализованными ECS-источниками. Приняты серверный конвейер агрегатов и его UI, серверное ядро RCF; результат TASK-35 завершает постоянный worker и восстановление после успешного коммита. Остаются API, UI детекторов, находки и финальная сквозная приёмка TASK-36–39. Доработка полного браузерного набора относится к TASK-37; проверки задач выбираются по влиянию. Единственная текущая сводка и отдельная открытая доработка внешнего E2E ведутся в [плане этапа 2](stages/stage2/plan2.md#1-текущее-состояние). Следующая постановка ещё не сформирована и не передана Исполнителю; старые локальные TASK/FIX не разрешают начать следующую работу.

## Дальнейшие этапы

Локальная LLM для расследования с ограниченным набором проверяемых инструментов, оповещения, отчёты и иные возможности исходного замысла требуют отдельных будущих постановок. Их упоминание не разрешает реализацию в этапе 2.

Если Главный архитектор не принимает этап, замечания сохраняются рядом с планом в `stage<n>_review_<номер ревью>.md`. Этапный архитектор продолжает тот же этап и план, связывает замечания с задачами/коммитами и повторно передаёт результат через человека; прежние ревью сохраняются. Подробный порядок — в [правилах ведения плана и доработки этапа](workflow.md#доработка-по-ревью-этапа).
